# Event Contract v1

这是生产目标契约。当前 v0.1 领域切片只实现归因核心所需的 scope、事件键、发生时间和身份集合；`ingest_time`、`schema_version`、`source_position` 及完整事件 envelope 将在 Kafka 接入阶段实现。

## 通用要求

所有原始事件必须携带：

| 字段 | 含义 |
|---|---|
| `event_id` | 上游生成的确定性幂等键 |
| `event_type` | `click`、`activation`、`register`、`pay` 等 |
| `event_time` | 业务实际发生时间，UTC 毫秒精度 |
| `ingest_time` | 进入采集系统的时间 |
| `tenant_id` | 发行主体或租户 |
| `game_id` / `app_id` | 游戏及应用范围 |
| `platform` | 微信、抖音、广点通、巨量等来源 |
| `schema_version` | 事件 Schema 版本 |
| `source_position` | Kafka topic、partition、offset 或等价来源位置 |

`event_id`、`click_id` 和 `activation_id` 必须是全链路稳定的命名空间键，例如由 `tenant_id + game_id + platform + upstream_id` 组成。裸平台 ID 不能跨游戏或租户直接作为去重键。

## 身份标识

标准事件中只保留：

```json
{
  "type": "oaid",
  "value_hash": "hmac_sha256(key, tenant + game + app + type + canonical_value)",
  "normalization_version": "oaid-v1",
  "key_version": "identity-key-v1"
}
```

- 原始 OpenID、OAID、IDFA 和设备标识不得进入归因核心。
- 普通 SHA-256 仅提供伪名化，不等于匿名化；生产环境对可枚举标识应使用带密钥的 HMAC，并制定密钥版本与轮换方案。
- 哈希/HMAC 输入必须包含 tenant、game、app 作用域；标准化结果必须携带 `normalization_version`，HMAC 实现还必须携带 `key_version`。
- 参与摘要的字段必须使用长度前缀或不可歧义的分隔编码，不能直接拼接可变长字符串。
- 不同身份类型使用独立规范化策略，Opaque Token 不得统一转小写。
- Canonicalization 策略由可信的 type/platform 配置选择，不能接受原始事件自行指定。
- 空值、全零值和共享占位符进入坏数据 Side Output，避免形成热 Key。
- 一个点击可以展开为多个 `(identity_type, identity_hash)` 窄索引行。

## 时间语义

- 归因 lookback：业务允许向前查找点击的窗口，当前为 7 天闭区间。
- 乱序 grace：等待正常迟到点击的工程时间，由各平台延迟分布决定。
- index watermark：点击索引已经完整可查到的事件时间进度。
- Lookup 只有覆盖完整窗口、全部身份、没有被截断且 watermark 已满足时，才能标记为 `AUTHORITATIVE`。

## 版本语义

归因输出必须包含：

```text
rule_id
rule_version
engine_version
decision_id
decision_version
supersedes_decision_id
```

`decision_version` 由最终物化层以 CAS 或幂等 Upsert 分配，归因纯函数不读取当前数据库序列。
